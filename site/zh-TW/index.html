你的 MQTT 裝置，
直接進「家庭」App。

一個 Homebridge 外掛，把 MQTT 主題變成 HomeKit 配件：燈、感應器、門鎖、恆溫器等等。它是 homebridge-mqttthing 持續維護的後繼版本，現有設定不用改就能用。

    直接換過來，不必從頭再來

    從 homebridge-mqttthing 轉過來嗎？config.json 完全不用動。配件區塊照樣寫 "accessory": "mqttthing"，codec 檔案和 apply 運算式也都照常運作。

    1. 移除 homebridge-mqttthing

      兩個外掛都使用 mqttthing 這個名稱，同時只能安裝其中一個。

    2. 安裝 MQTT Thing EX

      從 Homebridge UI 安裝，或使用 npm。

    3. 重新啟動 Homebridge 一次

      一次做完，只重新啟動一次。配件的身分不變，房間、場景和自動化都會保留。

    不需要重新配對。Homebridge 是以配件名稱來辨識配件，而不是外掛，名稱沒變，配件就還是同一個。

    每個 broker 一條連線，而不是每個裝置一條

    原本的外掛會替每個配件各開一條 MQTT 連線。選用的平台模式把所有裝置放進同一個區塊，共用一條連線：同一個 broker 上的二十四盞燈，只要一條連線，而不是二十四條。

    • 放心改名

      每個裝置都有固定的 id，名稱只是標籤，想改就改。

    • 設定出錯也不會弄丟配置

      設定有誤的裝置，會在 HomeKit 中保留原本的位置，房間和自動化都在，等你修好。錯誤會在啟動時寫進日誌。

    • 準備好再搬

      設定頁面會替你把配件搬到平台模式，並保留它們在 HomeKit 中的身分。配件模式也會持續完整支援。

    你會得到什麼

    homebridge-mqttthing 能做的都在，用 TypeScript 為 Homebridge 2 重新打造，並修好長久以來的問題。

    • 為大量裝置設計的設定頁面

      可搜尋的裝置清單、懂得每種類型有哪些主題的編輯器、可以安全編輯的 apply 函式、連線測試，以及即時主題探測。

    • 對小型裝置更溫和

      選用的發布佇列會控制訊息節奏，每個主題只保留最新的值，場景切換或拖動滑桿時，不會把低功耗裝置淹沒。

    • 訊息格式隨你

      codec 檔案、apply 運算式和 JSONPath（topic$.path）都照常運作，格式特殊的裝置也不必另外寫橋接程式。

    • Eve App 歷史紀錄

      溫度、濕度、氣壓、用電量等數據會記錄下來，顯示在 Eve App 的歷史圖表中。

    • 修好上游的問題

      啟動時多送的顏色訊息、自適應照明把燈打開、萬用字元訂閱、空訊息造成當機等等。

    • 為 Homebridge 2 準備好了

      採用新版 HomeKit API 與 ES 模組。可在 Homebridge 1.8 以上與 2.x 執行，npm audit 零弱點。

    幾分鐘就能設定好

    1. 安裝外掛

      在 Homebridge UI 開啟外掛頁面，搜尋 MQTT Thing EX 並安裝。

    2. 加入裝置

      開啟外掛設定，選擇新增，挑選裝置類型，填入 broker 和主題，當場就能測試連線。

    3. 重新啟動 Homebridge

      裝置會出現在「家庭」App 中，可以分配房間、加入場景，也能用 Siri 控制。

    需要 Homebridge 1.8 以上（支援 2.x）與 Node.js 18.17 以上。 完整設定說明（英文）
