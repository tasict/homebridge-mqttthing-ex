in Apple Home.

A Homebridge plugin that turns MQTT topics into HomeKit accessories: lights, sensors, locks, thermostats and more. It is the actively maintained successor to homebridge-mqttthing, and your existing configuration works unchanged.

Install in Homebridge View on GitHub

Free and open source. Works with Homebridge 1.8 or later, including 2.x.

    Switch over without starting again

    Coming from homebridge-mqttthing? Your config.json stays exactly as it is. Accessory blocks keep "accessory": "mqttthing", and codec files and apply expressions keep working.

    1. Uninstall homebridge-mqttthing

      Both plugins answer to the name mqttthing, so only one can be installed at a time.

    2. Install MQTT Thing EX

      From the Homebridge UI, or with npm.

    3. Restart Homebridge once

      Do it all in one go, with a single restart. Accessories keep their identity, so rooms, scenes and automations stay as they are.

    No re-pairing is needed. Homebridge identifies each accessory by its name, not by the plugin, and the names stay the same.

    One connection per broker, not per device

    The original plugin opens an MQTT connection for every accessory. Optional platform mode puts all your devices in one block and gives them a shared connection, so twenty-four lights on one broker need one connection instead of twenty-four.

    • Renaming is safe

      Devices carry a stable id, so the name is just a label. Change it whenever you like.

    • Mistakes don't cost you the setup

      A device with a broken configuration keeps its place in HomeKit, room and automations included, while you fix it. Mistakes are reported in the log at start-up.

    • Move when you are ready

      The settings screen moves accessories into platform mode for you and keeps their HomeKit identity. Accessory mode stays fully supported.

    What you get

    Everything homebridge-mqttthing did, rebuilt in TypeScript for Homebridge 2, with the long-standing problems fixed.

    • Settings built for big setups

      A searchable device list, an editor that knows each type's topics, apply functions you can edit safely, a connection test and live topic probing.

    • Gentle on small devices

      An optional publish queue paces messages and keeps only the latest value per topic, so scenes and slider drags don't flood a low-power device.

    • Your payloads, your way

      Codec files, apply expressions and JSONPath (topic$.path) all keep working, so devices with unusual payloads fit in without a custom bridge.

    • History in the Eve app

      Temperature, humidity, air pressure, power and more are recorded for the Eve app's history charts.

    • Upstream bugs fixed

      Spurious colour publishes at start-up, adaptive lighting turning lights on, wildcard subscriptions, crashes on empty payloads and more.

    • Ready for Homebridge 2

      Modern HomeKit APIs and ES modules. Runs on Homebridge 1.8 and later and on 2.x, with a clean npm audit.

    Set it up in a few minutes

    1. Install the plugin

      In the Homebridge UI, open Plugins, search for MQTT Thing EX and install it.

    2. Add a device

      Open the plugin settings, choose Add, pick the device type and enter your broker and topics. Test the connection right there.

    3. Restart Homebridge

      The device appears in the Home app, ready for rooms, scenes and Siri.

    Requires Homebridge 1.8 or later (2.x supported) and Node.js 18.17 or later. Full configuration reference
